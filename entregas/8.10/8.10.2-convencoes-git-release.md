## O que este passo pede

Registrar **convenções de branch**, **commit**, **release** e **versionamento**.

---

## Versionamento app

| Campo | Fonte |
|-------|-------|
| `version` | `pubspec.yaml` — `1.0.0+1` |
| `versionName` / `versionCode` | Flutter build name/number |
| Android `applicationId` | `com.example.alexandria` (alterar antes Play Store) |
| Nome exibido | **Alexandria** |

Formato semver Flutter: `MAJOR.MINOR.PATCH+BUILD` (ex.: `1.0.0+1`).

---

## Convenções Git (recomendadas)

| Item | Convenção |
|------|-----------|
| Branch principal | `main` |
| Features | `feature/descricao-curta` |
| Fixes | `fix/descricao-curta` |
| Documentação | `docs/etapa-8.x` ou commit direto em `entregas/` |
| Commits | Imperativo — ex.: `Adiciona leitor EPUB`, `Documenta etapa 8.9` |
| Tags release | `v1.0.0` |

---

## Convenções de documentação (`entregas/`)

Ver `CONVENCOES.md`:

```
{etapa}.{passo}-{slug}.md
{etapa}.{passo}-{slug} (prints).md   ← quando exigir capturas
```

Exemplo: `8.9.1-testes-minimos.md`, `8.3.4-prototipo-telas (prints).md`.

---

## Processo de release (resumo)

1. Atualizar `pubspec.yaml` (version)  
2. Conferir `.env` / `.env.example`  
3. `flutter analyze`  
4. `flutter test` (corrigir `widget_test.dart` se necessário)  
5. `flutter build apk --release` e/ou build Windows  
6. Homologar com **8.9.5** (termo de aceite)  
7. Tag `vX.Y.Z` + distribuição do pacote  

---

## O que não versionar

- Keystore Android de produção  
- `.env` com URLs/credenciais sensíveis  
- `build/`  
- `.dart_tool/`  
- Fotos de perfil cropadas em runtime (`profile_*.jpg`)
