# 8.5 — Backend, APIs padronizadas e segurança

**Projeto:** Alexandria — Biblioteca Digital (Globaltec Educacional)  
**App:** Flutter `alexandria` 1.0.0+1  
**Formato:** um documento por etapa (padrão ByGames 15.6)

---

## 1. Arquitetura

```
[App Flutter Alexandria]
   ├─ Login / sessão / perfil     ──HTTPS──►  [API PHP ebook]
   ├─ Catálogo / leitura / listas ──HTTPS──►  [api.php + user_*]
   └─ Contas / acervo (ADM)       ─────────►  [Painel ADM PHP e/ou Kotlin]
                                                         │
                                                         ▼
                                                   [MySQL compartilhado]
```

| Camada | Situação |
|--------|----------|
| Cliente | Flutter (`http`, `flutter_dotenv`, `EbookApiClient`) |
| API do leitor | PHP `ebook/` — fora do repo Flutter |
| Painel PHP | Funcional; mesmo banco |
| Painel Kotlin | Funcional; migração **parcial**; mesmo banco |
| Auth leitor | E-mail + senha via **POST**; sem JWT |

Base URL só no `.env` → `AppConfig` → `EbookApiClient`.

| Variável | Obrigatória | Uso |
|----------|-------------|-----|
| `EBOOK_SITE_BASE_URL` | Sim | Base do painel/API |
| `EBOOK_API_BASE_URL` | Não | Padrão `{SITE}api.php` |
| `EBOOK_IMAGES_BASE_URL` / `EBOOK_THUMBS_BASE_URL` | Não | Capas / thumbs |

## 2. Contratos ativos

| ID | Path | Método | Cliente |
|----|------|--------|---------|
| API-01 | `user_login_api.php` | **POST** form (`email`, `password`, `type=Normal`, `auth_id`) | `EbookApiClient.login` |
| API-02 | `user_profile_api.php` | GET | perfil |
| API-03 | `user_profile_update_api.php` | POST multipart | update perfil |
| API-04 | `privacyPolicy.php` | GET | políticas |
| Catálogo | `api.php?method_name=…` | GET | home, livros, fav, wishlist, progresso, etc. |

**Login — body:** senha **não** vai na query. PHP lê `$_POST` (fallback `$_GET` só legado). Envelope `EBOOK_APP` / `Galileu`.

**Senha no servidor:** BCrypt/Argon2 → `password_verify`; plaintext legado → aceito e **upgrade BCrypt** no login OK (`reader_verify_and_upgrade_password`).

Arquivos: `ebook/user_login_api.php`, `ebook/includes/function.php`, `lib/core/api/ebook_api_client.dart`.

## 3. Autenticação e segurança

| Tema | Situação |
|------|----------|
| Login | **POST** + HTTPS (homolog/prod) |
| Sessão | SharedPreferences `session_user` |
| Token | Sem JWT |
| Cadastro / esqueci senha | Só ADM |
| Segredos no app | Só URL pública; `.env` gitignored |
| Storage | SharedPreferences (sem secure storage ainda) |

**Por que POST mesmo com BCrypt:** hash protege o banco; GET colocava senha na URL (logs). POST + HTTPS + BCrypt cobrem transporte e persistência.

Pendências pós-MVP: JWT, secure storage, remover fallback GET, prepared statements em todo o login, rate limit.

---

## 4. Coexistência dos painéis

Ambos os ADMs (PHP e Kotlin) usam o **mesmo MySQL**. Contas Kotlin (BCrypt) logam no app via PHP. API do leitor em Kotlin ainda **não** substitui o `ebook/` PHP.

---

## 5. Smoke e limites

1. POST com conta válida → `success: "1"`; senha fora da URL  
2. Legado plaintext → login OK + hash `$2…`  
3. Conta Kotlin BCrypt → login OK  

| IN | OUT |
|----|-----|
| Contratos leitor + login POST | Backend Kotlin do leitor |
| Upgrade de senha | Pen-test / WAF (infra) |
| Documentar coexistência ADM | Desligar painel PHP |
