# 8.1.4 — Passo 4: Validação de termos de navegação

**Projeto:** Alexandria — Biblioteca Digital (Globaltec Educacional)  
**Etapa:** 8.1 — Menu padrão, módulos, perfis e permissões

---

## O que este passo pede

Validar **termos de navegação** para evitar nomes **duplicados** ou **ambíguos** na UI e na documentação.

---

| Termo UI | Significado | Onde aparece |
|----------|-------------|--------------|
| **Alexandria** | Nome do produto / marca | Splash, Login |
| **Biblioteca Digital** | Subtítulo do produto | Splash |
| **Início** | Aba principal — destaques e seções | Bottom navigation |
| **Explorar** | Aba de descoberta — gêneros e autores | Bottom navigation |

| **Autores** | Lista/carrossel de autores | Explorar |

## Termos proibidos na UI ativa

| Termo | Problema | Resolução |
|-------|----------|-----------|
| **Criar conta** / **Cadastro** / **Sign up** | Contas provisionadas pela Globaltec / ADM | Não usar no app Flutter |
| **Esqueci a senha** / **Recuperar senha** | Suporte Globaltec / ADM | Não usar no app Flutter |

| Evitar na UI | Preferir | Motivo |
|--------------|----------|--------|
| Home | **Início** | Consistência com bottom bar |
| Search | **Explorar** | Label da aba |
| Wishlist | **Ler Depois** | Termo amigável ao leitor |
| Category | **Gênero** / **Gêneros** | Vocabulário literário |
| Featured | **Destaque** | Título do AppBar |
| Settings (genérico) | **Configurar perfil** ou **Políticas de uso** | Dois contextos distintos |

---

## Conflitos resolvidos / termos a observar

| Termo | Problema | Resolução |
|-------|----------|-----------|
| **Buscar livros** | Usado no Início **e** no Explorar | OK — mesmo modo de busca, contextos diferentes |
| **Explorar** (aba) vs **Explore livros e categorias** (placeholder) | Similar | Placeholder só quando categorias vazias |
| **Ler Depois** vs **Na lista** | Dois estados do mesmo recurso | **Ler Depois** = ação; **Na lista** = já adicionado |
| **Favoritar** vs **Favorito** | Dois estados | Toggle no mesmo botão — sem ambiguidade |
| **Configurações** (`SettingsScreen`) vs **Configurar perfil** | Nomes parecidos | `SettingsScreen` existe mas acesso principal é via **Configurar perfil** no Perfil |
| **Leitor Assíduo** | Badge fixo no perfil | Não confundir com perfil RBAC — é texto decorativo |

---

## Ambiguidades a evitar na documentação futura

| Evitar | Preferir | Motivo |
|--------|----------|--------|
| “Ebook” genérico | **Livro** ou **Alexandria** | Marca do produto |
| “Biblioteca” como nome do app | **Alexandria — Biblioteca Digital** | Tagline, não nome curto da aba |
| “Perfil” vs “Conta” | **Perfil** = aba; **Configurar perfil** = edição | Dois níveis distintos |
| “Acervo” na UI | Manter só na doc técnica | Usuário vê conteúdo, não o ID da organização |
| “Wishlist” em docs funcionais | **Ler Depois** | Alinhar com UI |

---

## Validação de duplicidade — bottom bar e títulos de tela

| Label | Ocorrências no fluxo ativo | Status |
|-------|----------------------------|--------|
| Início | 1 (aba) | ✓ OK |
| Explorar | 1 (aba) + placeholder vazio | ✓ OK |
| Perfil | 1 (aba) + AppBar | ✓ OK |
| Destaque | 1 (AppBar Início, sem busca) | ✓ OK |
| Buscar livros | 2 (AppBar Início e Explorar, mutuamente exclusivo com título anterior) | ✓ OK — estados alternados |
| Meus Favoritos | 1 (seção Perfil) | ✓ OK |
| Ler Depois | 1 (seção Perfil) + botão detalhe | ✓ OK — mesmo conceito |
| Políticas de uso | 2 (EditProfile + SettingsScreen) | ✓ OK — mesmo conteúdo |

**Resultado:** sem labels duplicados conflitantes no menu principal.
