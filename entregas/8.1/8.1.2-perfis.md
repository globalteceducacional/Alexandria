## O que este passo pede

Definir **perfis de usuário** e o que cada perfil pode **ver**, **criar**, **editar** ou **aprovar**.

---

## Perfis no app (estado atual)

O Alexandria **não implementa RBAC** (controle de acesso por papéis) no cliente Flutter. Existe **um tipo de usuário autenticado** com as mesmas capacidades na UI.

| Perfil | Descrição | Onde existe |
|--------|-----------|-------------|
| **Usuário autenticado** | Conta com login/senha na API Globaltec; pode ter `acervo_id` (catálogo da organização) | App Flutter |
| **Visitante** | Sem sessão — **não acessa o app** (redirecionado ao Login após Splash) | — |

> **Organização / acervo:** o campo `acervoId` em `AppUser` filtra livros, categorias, autores e seções retornados pela API (`acervo_id` nos endpoints).

## Regras de negócio ligadas a permissões

| Regra | Implementação |
|-------|---------------|
| Login obrigatório | `AuthViewModel.isLoggedIn` — sem modo convidado |
| Criação de conta | **Globaltec / painel ADM** — sem rota de cadastro no app |
| Configurar perfil sensível | `_SettingsPasswordDialog` exige re-login antes de `EditProfileScreen` |
| Sair da conta | `EditProfileScreen` → `AuthViewModel.logout()` — **sem** confirmação de senha |
| Favoritos / Ler Depois | Exigem `userId`; mensagem se não autenticado (detalhe do livro) |
| Catálogo filtrado | `acervoId` do usuário repassado às chamadas da API |
