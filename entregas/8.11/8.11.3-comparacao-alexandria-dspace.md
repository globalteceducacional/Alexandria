# 8.11.3 — Passo 3: Comparação prática — Alexandria × DSpace

**Projeto:** Alexandria — Biblioteca Digital (Globaltec Educacional)  
**Etapa:** 8.11 — Referências modelo, benchmark e comparação prática

---

## O que este passo pede

Comparar **fluxo**, **menu**, **onboarding**, **segurança**, **suporte** e **documentação** com a solução desejada (Alexandria).

---

## Contexto das soluções

| | **Alexandria (desejado)** | **DSpace (referência)** |
|--|---------------------------|-------------------------|
| Tipo | App Flutter — biblioteca digital escolar | Plataforma web — repositório institucional |
| Usuário principal | Leitor (aluno) com conta provisionada | Pesquisador, bibliotecário, admin institucional |
| Conteúdo | Livros PDF/EPUB por acervo | Itens digitais diversos + metadados acadêmicos |
| Backend | API PHP Globaltec | Java + PostgreSQL |

---

## Comparação — fluxo

| Etapa | Alexandria | DSpace |
|-------|------------|--------|
| Entrada | Splash → Login ou Main | Homepage web → browse/search |
| Autenticação | Login obrigatório (e-mail/senha) | Login opcional / roles (visitante vs autenticado) |
| Descoberta | Início (destaques) + Explorar (gênero/autor) + busca | Browse por comunidade/coleção + search avançado |
| Consumo | Leitor PDF/EPUB in-app | Download ou viewer web |
| Retomada | Continuar lendo (local + API) | Histórico / bookmarks (conforme config) |
| Listas pessoais | Favoritos + Ler Depois | Submissões, workspace (admin/autor) |
| Saída | Logout opcional em Config perfil | Sessão web padrão |

**Conclusão:** fluxos **complementares**, não equivalentes — DSpace é repositório; Alexandria é **leitor mobile** sobre acervo já publicado.

---

## Comparação — menu / navegação

| Alexandria | DSpace (dspace-angular) |
|------------|-------------------------|
| 3 abas fixas: Início, Explorar, Perfil | Menu web: Home, Browse, Search, Submit, Admin (conforme perfil) |
| Push para detalhe/leitor | Rotas Angular por comunidade/item/estatísticas |
| Busca inline no AppBar | Search dedicado com filtros |
| Sem menu admin in-app | Painel admin robusto no frontend |

**Conclusão:** Alexandria mantém menu **simples para leitor** — adequado à escola; DSpace exige mais opções para gestão institucional (fora do escopo do app).

---

## Comparação — onboarding

| Aspecto | Alexandria | DSpace |
|---------|------------|--------|
| Primeiro uso | Splash ~2 s → Login | Instalação server + config YAML (admin) |
| Cadastro usuário | Globaltec / ADM (sem in-app) | Admin cria grupos/epersons ou registro configurável |
| Tutorial in-app | Não | Vídeos de treinamento na wiki |
| Demo | App + credencial teste | “Try DSpace” + Docker compose |
| Onboarding escola | Kit de logins + manual 8.8 | Documentação de instalação + service providers |

**Conclusão:** Alexandria prioriza **onboarding operacional** (coordenação/TI); DSpace prioriza **onboarding técnico** (implantação do repositório).

---

## Comparação — segurança

| Aspecto | Alexandria | DSpace |
|---------|------------|--------|
| Autenticação | Login API (**POST** — senha no body; ver 8.5) | REST auth, grupos, policies granulares |
| Autorização | Um perfil leitor + filtro `acervoId` | Group-based access control (RBAC avançado) |
| Sessão | `session_user` SharedPreferences | Sessão/token REST |
| Dados sensíveis | Gate senha para config perfil | Policies por item/comunidade |
| HTTPS | Obrigatório em produção | Padrão em implantação institucional |
| Auditoria | Parcial (servidor + progresso) | Metadados, proveniência, preservação |

**Conclusão:** DSpace é **referência de granularidade**; Alexandria cobre MVP escolar com **acervo isolado por usuário** — login POST concluído (8.5); policies avançadas no ADM.

---

## Comparação — suporte

| Aspecto | Alexandria | DSpace |
|---------|------------|--------|
| L1 | Professor / coordenação (8.8.3) | Mailing lists comunitárias |
| L2 | TI escola | dspace-tech@googlegroups.com |
| L3 | Globaltec | Lyrasis + service providers registrados |
| FAQ | 8.8.2 erros comuns | Wiki Troubleshoot + Stack Overflow |
| SLA | Orientativo na doc 8.8 | Comunidade + contratos com providers |

**Conclusão:** modelo de **escalonamento em camadas** do Alexandria (8.8) é análogo ao DSpace (comunidade → técnico → vendor).

---

## Comparação — documentação

| Aspecto | Alexandria | DSpace |
|---------|------------|--------|
| Estrutura | `entregas/8.x/` (5 passos por etapa) | Wiki Lyrasis + README + RestContract |
| UX / prints | E-001…E-008 em 8.3.4 | Screenshots na wiki e site |
| API | 8.2.3, 8.6.3 | RestContract GitHub (OpenAPI-style) |
| Manual operação | 8.8 consolidado | Admin/workflow docs na wiki |
| Homologação | 8.9 termo de aceite | Testes Maven + CI GitHub Actions |

**Conclusão:** Alexandria adota **processo documental** similar em espírito; DSpace é referência para **contrato de API formal** e **testes automatizados**.
