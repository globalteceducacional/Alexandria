## Decisões aplicáveis desta etapa

| ID | Decisão | Fundamentação |
|----|---------|---------------|
| BMK-01 | **Não** adotar DSpace como backend | API PHP Globaltec já integrada |
| BMK-02 | Manter menu 3 abas (leitor) | DSpace é admin-heavy; escola precisa simplicidade |
| BMK-03 | Inspirar suporte L1→L3 | Paralelo comunidade → tech → vendor (8.8.3) |
| BMK-04 | Manter docs de API em 8.2.3 / 8.6.3 | Contrato ebook documentado no MVP |
| BMK-05 | Login POST concluído (8.5) | Gap restante: JWT / policies granulares vs DSpace |
| BMK-06 | Manter `entregas/8.x` como wiki interna | Equivalente funcional à wiki Lyrasis |
| BMK-07 | Preservar PDF/EPUB in-app | Alinhado à promessa “preserva formatos” do DSpace |
| BMK-08 | ADM web fora do app | Submissão/gestão no painel — como DSpace admin separado |

## Conclusão do benchmark

| Referência | Papel para Alexandria |
|------------|----------------------|
| dspace.org | Visão de produto repositório, comunidade, preservação |
| DSpace/DSpace | Arquitetura API-first, testes, documentação técnica |
| dspace-angular | Referência UX web (browse/search) — **não** portar UI |

**Gap principal vs referência:** policies/RBAC granulares no ADM. Login POST resolvido (8.5). Práticas adotadas: ADP-01…ADP-10 em `8.11.4`.

**Gap aceito:** Alexandria não é repositório institucional completo — é **leitor mobile** da linha Globaltec.
